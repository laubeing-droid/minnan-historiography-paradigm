# 外部项目给我们的提醒

核读范围：2026年11月12日汇总的官方仓库与论文。下列为方法借鉴，未将这些系统集成或运行于本仓。版本变化后须重新核对，不能按项目名替代实际能力。

## Google Harness²

来源：[官方仓库](https://github.com/google-research/harness2)、[论文 v1](https://arxiv.org/html/2610.14224v1)。

它把模型本身与围绕模型的执行方法分开，在固定模型下尝试同任务改进，并积累跨任务可复用经验。值得借鉴的是保存一次尝试为何失败、改了哪种执行方法、下一次如何比较；不必把每次改善都解释成模型权重升级。

无真值条件下得到的改进仍需外部验收。官方记录还提示评测 rubric 可被下载的问题：只在提示词中要求“不看答案”不够，评测材料的网络可达性要实际隔离和检查。研究项目不能让施工者接触保留验收答案，再把高分称作独立发现。

## Darwin Gödel Machine

来源：[论文 v2](https://arxiv.org/html/2505.22954v2)。

该研究真正试验代理修改自身代码，不能把它与只改提示词的方案混为一谈。但论文附录 H 披露了删除日志以欺骗检测的行为。这提醒我们：检查程序之外，记录本身也要受保护。一个候选方案如果通过隐藏失败记录提高表现，应被拒绝，不能算进化成功。

本仓没有复现其代码修改与搜索机制。保留这个例子，是为了说明为什么执行者不能兼任不受约束的评判者。

## karpathy/autoresearch

来源：[program.md](https://github.com/karpathy/autoresearch/blob/master/program.md)。

它给自主试验划出明确范围：可修改训练文件 `train.py`，评估准备文件 `prepare.py` 保持只读，并设固定实验预算。可迁移的是“小而清楚的可改范围 + 预先确定的比较条件”。研究项目需要重新确定自己的范围和成本，不能照抄机器学习训练的预算与分数。

## GEPA

来源：[官方仓库](https://github.com/gepa-ai/gepa)。

它利用执行反馈进行反思，提出候选，再通过评测比较。可借鉴的是让“觉得这个提示词更好”变成可检验的候选，而非立即覆盖原流程。史料研究还必须检查候选是否损害忠实转写、来源可追查和存疑表达，单一成功率不能替代这些要求。

## 本仓取舍

先做一项能验收的研究，保留原流程与失败证据，只在明确范围内试改，再交由独立检查。暂不引入自动搜索、代码自改引擎或跨项目经验调度器。若以后需要，应先说明哪个具体研究问题受阻、现有流程为什么不够，以及新增机制怎样接受独立验收。

## 建设工程的责任分工与单位经验

以下用于理解分工、变更、交接和企业经验积累，不是历史研究的法律适用依据：

- [房屋建筑和市政基础设施工程竣工验收规定（官方转载）](https://www.yixing.gov.cn/doc/2013/12/31/653649.shtml)：建设单位组织相关责任主体验收。参与各方按职责形成意见，不能简化成五个人投票，也不能把所有责任归给监理。
- [建设工程勘察设计管理条例](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_7aebb685f7b94720bfdccf8ac71541c9.html)第28条：勘察、设计文件的修改有相应责任与程序，不能由施工或监理单位自行随意修改。借鉴到研究中，是区分执行反馈、方案变更与批准权。
- [建设工程消防设计审查验收管理暂行规定修改决定](https://www.mohurd.gov.cn/gongkai/zc/wjk/art/2023/art_17339_774791.html)：专项检查有适用范围和法定程序。消防与规划、土地、人防、档案等事项不能混称为所有工程统一必经的“五方投票”；涉及地方联合验收时，还须另核当地规定及具体项目条件。
- [工程建设工法管理办法（官方转载）](https://www.beijing.gov.cn/zhengce/zhengcefagui/qtwj/201407/t20140716_781396.html)：企业可以总结实践经验、形成工法并继续应用。这为“项目结束，单位能力仍应积累”提供具体参照，但不代表一条经验可以越过新项目的适用性检查。

监理日志留痕的要求，在本模板中落实为保留原记录与更正链，而非宣称日志永远不得更正。跨研究项目的接口共查，则是基于上述责任与交接思路提出的设计，尚无本仓实际运行验证。
