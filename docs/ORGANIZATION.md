# 谁做什么，怎么交接

建设工程给这个范式提供的启发，是把目标、材料条件、方案、实施和监督各自的责任说明白。它不是要求历史研究照搬工程合同或行政程序。

| 研究中的责任 | 建工类比 | 本次必须交代什么 |
|---|---|---|
| 提出目标、范围和采用决定 | 业主/建设单位 | 为什么做，交付什么，公开到哪里 |
| 查材料条件与缺件 | 勘察 | 有什么、没有什么，来源与适用性 |
| 研究设计 | 设计 | 方法怎样回答问题，替代解释怎样检查 |
| 统筹工序与交接 | 总包 | 依赖、分工、版本、冲突及最终汇总 |
| 具体取材、转写、计算、写作 | 分包班组 | 实际做法、产出、错误及未完成项 |
| 过程监督与成果复核 | 监理及相应检查者 | 查了什么、证据、独立性、处理意见 |

这些是职责，不是机械的上下级链。小项目可以兼岗，但执行者自己复查不能冒称独立验收。多个模型一致也不能代替回查原材料。涉及研究设计或验收标准变更，要交回相应负责人决定；监理式角色可以指出问题，不能自动取得所有人的决定权。

## 改动如何处理

执行者提出问题，说明影响范围和建议。总调度确定哪些工序或交付会受影响。方法或标准的责任方检查理由，必要时由独立复核者测试，再决定采用、试验或拒绝。记录原方案、新方案、启用版本及旧成果怎样处理。

新标准发现旧成果有缺陷，不应要求旧成果先“全通过”才能启用，否则会把旧漏洞永久保存。旧缺陷单列，确定迁移或重做范围；未迁移成果保持原状态，不偷偷改成新标准通过。

## 共同检查不等于投票

工程中的竣工验收与专项检查各有范围与程序，研究只借鉴多方按责任核对的思路。来源、翻译、统计、隐私和权利等专门问题，按实际风险安排检查，不强制每个项目全部设置。

跨仓交接要有一个明确对象：哪个版本的材料、哪些字段和单位、怎样处理未知值、何种许可。上下游共同跑一个样例，检查信息是否损失或变义。双方各自测试通过，仍可能在接口上出错。[交接检查模板](../templates/交接检查.md)用于有这种需要的项目。

## 日志与知识怎样保存

原始材料、执行日志、失败记录、验收意见和批准记录分别保留。记录可更正，但要留下旧值、原因、日期和责任人。新工具、新人员和新模型接手时，应能知道哪些是观察，哪些是推测，哪些已被推翻。

项目内的修复记在[一次改进记录](../templates/一次改进记录.md)；单位跨项目积累记在[单位工法卡](../templates/单位工法卡.md)。后者可以引用前者，不重复抄整段历史。采用经验不继承旧项目的权限与合格资格。
