# 闽南文史研究范式

**minnan-historiography-paradigm · fantastic-spoon（神奇汤勺）🥄**

教 AI 怎么吃饭，也教它别乱喂人。

以后新开一项闽南文史研究，不必每次从一张白纸开始。这个仓库提供可复制的研究组织模板：怎样提出问题、查材料、选方法、实际做、检查结果、形成解释，以及怎样把一次失败留给下一次研究。

这里关心的不只是一份文献能不能录完，还包括人们怎样劳动、生活、组织社会，语言和文化怎样传承，又怎样失去延续的条件。AI可以承担很多工序，但材料如何支持结论、哪些解释仍然站不住，需要说清楚。

这是范式模板，不是工作台或工具箱。当前交付是可使用的文档与项目骨架，没有安装依赖、自动执行引擎或已经验证的通用RSI系统。它需要由真实研究继续检验。

## 新项目从这里开始

1. **复制 [project-template/](project-template/)** 的五个入口：项目说明、材料说明、研究方案、任务看板、交付说明。填上题目、范围、完成条件和权限。已有看板就只链接它，不重复维护。
2. 按问题选择[六种研究模块](research-types/README.md)：文献对勘、地方志时间线、人口空间、文化实践田野、人物网络、语言与跨地域比较。每种都有样例和专门检查问题。
3. 按需复制[研究记录](templates/研究记录.md)、[论证与复核](templates/论证与复核.md)、[交接检查](templates/交接检查.md)。不用的栏目可删，重要证据不能省。
4. 开始试做，随材料修正问题和解释。把[Agent使用说明](AGENTS.md)连同具体任务交给执行者。模板本身不授予任何操作权限。
5. 遇到可重复的失误，用[一次改进记录](templates/一次改进记录.md)修本项目，再用[单位工法卡](templates/单位工法卡.md)保存可迁移经验。新项目仍要重新判断和验收。

仓库尚未启用GitHub的Template repository属性。现在可复制所需文件，或克隆本仓后把项目骨架用于自己的仓。记录采用的提交版本，不继承模板的示例结论、旧项目状态或权限。

## 这套范式依据什么

| 方向 | 阅读入口 | 具体用途 |
|---|---|---|
| 两个实际项目的经验 | [书稿与文献仓教训](docs/REPOSITORY_EXPERIENCE.md) | 来源补证、实际运行、错误修复、内容与程序检查分开 |
| GitHub项目与论文 | [方法参照](docs/METHOD_REFERENCES.md)、[RSI外部研究](docs/EXTERNAL_REFERENCES.md) | 可复查组织、反思候选、边界与独立验收 |
| 建设工程的责任分工 | [组织与交接](docs/ORGANIZATION.md) | 目标、勘察、设计、总分包、监督、变更和联验；只借鉴，不套法律 |
| 区域历史与地方文化研究 | [研究指南](docs/RESEARCH_GUIDE.md) | 时空范围、生产生活、文化实践、反证与竞争解释 |
| 研究所需的其他保护 | 五入口及[Agent说明](AGENTS.md) | 权利、隐私、存疑、版本、协作、公开与未完成说明 |

## RSI怎样服务研究

先有具体项目和清楚的完成目标，再谈自我改进。否则容易变成“许愿池式进化”：永远要求系统更聪明，却不把一本书对完。

[RSI说明](docs/RSI.md)分开三件事：项目内改工艺、单位跨项目积累能力、上下游项目共同检查接口。执行者可以提出改法，不能自行改验收标准、保留样本或失败日志。[来源与实现边界](docs/RSI_EVIDENCE.md)同时列出源仓有代码的部分、只有设计的部分，以及尚未堵住的反例。

## 三个仓各做什么

- [《一种闽南文史的未来：基于人工智能与现代研究方法》](https://github.com/laubeing-droid/minnan-historiography-book)：展开研究问题、方法与案例。
- [闽南—西班牙文献语料库](https://github.com/laubeing-droid/minnan-spanish-corpus)：在具体文献上施工，留下材料、教训与程序。
- **本仓**：提炼可以复制的研究组织方式。工作台是另一个项目，不在这里冒充已经提供。
